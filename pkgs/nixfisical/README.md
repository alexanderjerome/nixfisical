# nixfisical

Declarative management of a self-hosted [Infisical](https://infisical.com)
instance, driven from SOPS-encrypted secrets and a manifest generated from
NixOS configuration. A port of an Ansible role that did the same two jobs from
inside a playbook run.

## The two commands

`nixfisical bootstrap` turns a freshly deployed, uninitialised instance into a
usable one: superadmin, organization, and a `fleet-sync` Universal-Auth machine
identity. Every credential it creates is written to a single SOPS-encrypted
admin file (default `secrets/infisical-admin.yaml`), which is encrypted before
the process exits — if encryption fails, the plaintext is deleted rather than
left behind.

It is safe to re-run. Unlike the Ansible role, which treated "the admin file
exists" as proof of a completed bootstrap, this proves it by logging in with
the recorded machine identity. If the file exists but cannot authenticate, the
command stops with exit code 2 rather than re-bootstrapping over a live or
rebuilt instance.

```sh
nixfisical --url https://infisical.internal \
  bootstrap --organization fleet \
            --admin-email ops@example.com \
            --git-commit
```

The superadmin password is generated (`secrets.token_urlsafe(32)`) unless you
point at one with `--admin-password-from FILE:KEY`, or `--admin-password-from
KEY` together with `--secrets-file`. `--admin-email-from` takes the same two
forms. `--git-commit` commits the encrypted admin file in its own repository
and never pushes.

`nixfisical sync` makes the instance match a manifest: it creates missing
projects, environments and folders, upserts each secret's value out of SOPS,
and prunes secrets the manifest no longer declares. It authenticates as the
machine identity, so the superadmin password is never read on this path.

```sh
nixfisical sync --manifest ./manifest.json --root . --dry-run
```

Always dry-run first. The dry run performs every read — including decrypting
each SOPS file, so a rotated-away key is caught — and reports exactly what it
would create, update and delete. It prints coordinates only; no code path in
this package prints a secret value.

Two supporting commands: `nixfisical validate --manifest ...` checks a manifest
offline, and `nixfisical status` reports reachability plus whether the sync
identity can still log in. `status` is the intended guard in front of
`bootstrap` in a deploy script.

## The manifest

A JSON array, generated by the Nix half of this repo:

```json
[
  {
    "sopsKey": "services/bitcoin/rpc_password",
    "sopsFile": "secrets/bitcoin.yaml",
    "project": "bitcoin-nodes",
    "environment": "prod",
    "folder": "/mainnet",
    "name": "RPC_PASSWORD",
    "groups": ["developers"],
    "hosts": ["btc-mainnet"]
  }
]
```

`sopsFile` is per entry — the main improvement over the role, which assumed one
global secrets file. It may be omitted only when `--secrets-file` supplies a
default. `groups` and `hosts` are carried through and reported; access
reconciliation is out of scope for v0 (the role did it with direct Postgres
writes, which is not something this tool will do).

## Exit codes

| Code | Meaning |
| ---- | ------- |
| 0 | success |
| 1 | runtime error (network, API, SOPS, git) |
| 2 | validation failure, or a re-bootstrap that was refused |

## Running it

`sops` must be on `PATH` with the operator's keys resolvable; `nixfisical` shells
out to it for every decrypt. Python 3.11+, with `click`, `httpx` and `PyYAML`.

The flake at the repo root packages this, so the normal invocation is:

```sh
nix run .#nixfisical -- sync --manifest ./manifest.json --dry-run
```
